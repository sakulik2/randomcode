# 随机捞仓库

随机抓一批 GitHub 公开仓库，铺成一张印刷品。没有推荐算法，没有热榜，抽到什么就是什么。

纯静态前端，不需要后端，不需要登录。

## 跑起来

```bash
npm install
npm run dev
```

## 难点不在前端

GitHub 没有「给我一个随机仓库」的接口，随机性得自己造。做法是随机挑一段
`created:` 时间窗，再随机翻其中一页。这条路上有几个实测出来的坑：

**搜索结果硬上限 1000 条。** 翻到第 11 页直接报
`Only the first 1000 search results are available`。所以时间窗必须窄到
`total_count` 落在 1000 以内，否则抽样只会反复命中窗口里最热门的那一小撮，
表面随机实际是个排行榜。程序会先探一次 `total_count`，超了就按比例收窄窗口重来。

**仓库创建密度涨了约 150 倍。** 一小时窗口在 2012 年只有 90 个仓库，2026 年有 13808 个。
固定窗宽在老年代什么都抽不到，在近年直接撞上限，所以窗宽按年代自适应。

**星数门槛的留存率随年代变化**，这个最容易漏。`stars:>=100` 在 2011 年的仓库里
留存约 2.5%，2021 年只有 0.11%，差 23 倍 —— 老仓库有十几年时间攒星。
所以留存率表还要再乘一个年龄系数。

**真·随机的 GitHub 是一片作业仓库。** 实测随机抽 100 个：0 个有星，只有 40 个有描述，
内容是 `test1`、`Class-95-defective-piece` 这种。加 `stars:>=5` 门槛后
97 个有描述、90 个有语言。所以星数滑杆是双模式的开关，拉到最左就是不加任何门槛的原始随机 ——
那些 0 星仓库会如实出现，那是随机性没造假的证据。

## 免 token 怎么够用

`api.github.com` 的 CORS 是全开的（`Access-Control-Allow-Origin: *`，`/rate_limit` 也一样），
所以浏览器可以直连，不需要后端或代理，配额响应头也读得到。

免 token 的搜索配额是 10 次/分钟。撑住它靠**储备池**：每次请求拿 `per_page=100`，
但一屏只铺 12 张卡，剩下 88 个留在内存里，后续几次「再抽一批」直接从池里取，不发请求。
一次请求约等于 8 批。

界面角落可以填自己的 token，把配额提到 30 次/分钟。token 只进浏览器的
localStorage，不进代码、不进构建产物。不填也能正常用。

## 三种抽法

| 模式 | 怎么抽 | 代价 |
|---|---|---|
| 精选（默认） | 随机时间窗 + 星数门槛 + 随机翻页 | 排序偏热门，随机性靠随机翻页保证 |
| 原始（滑杆拉到 0） | 窄时间窗，不加任何条件 | 大部分是 0 星作业仓库 |
| 深水区 | `/repositories?since=<随机 id>` 走原始 id 空间 | 真正无偏，但字段贫，要额外一次请求补全 |

深水区走的是 core 配额（60 次/小时）。它返回的行没有 stars/language/topics，
约三分之一是 fork，所以用搜索接口的 `repo:A repo:B` 堆叠查询（一次约 12 个）补全元数据。

## 分享链接能复现

种子写在 URL 里，同一个种子会抽出同一批仓库 —— 就是界面上那个印次号。
采样范围按天对齐，不然种子每秒都在漂。

## 视觉

Riso 油墨印刷。四色油墨（Federal Blue / 荧光粉 / 黄 / 平黑）叠印，零圆角、零阴影，
卡片尺寸随星数变化。语言不映射到 GitHub 官方色，而是确定性地落到四色之一 ——
一台小印刷机不会装 60 个油墨鼓。

标题字体拉丁走 Big Shoulders Display，中文走 ZCOOL QingKe HuangYou（逐字回退，
因为前者不含中文字形）。另有一套终端主题，同一份数据换成深色等宽的日志。
